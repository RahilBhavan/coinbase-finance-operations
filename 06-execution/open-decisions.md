# Unresolved decisions and fallbacks

| Decision/gap | Why it matters | Resolution gate | Fallback |
|---|---|---|---|
| Current role and eligibility | determines whether project is worth building | official accessible posting or recruiter confirmation; major, skills, location, application count | keep as concept; build Credit first |
| Student's implementation skills | affects credible stack and hours | inventory SQL/TypeScript/Python/Excel ability | Python + SQLite + CSV, static HTML |
| x402 revision | mutable main branch can drift | pin reviewed commit/release before fixtures | preserve local schema snapshot and divergence note |
| Release finality stage | changes delivery latency/risk | reviewer chooses business risk tolerance | run both L2-inclusion and L1-batch-finality policies |
| Delivery acknowledgment | determines closure evidence | define client/server proof and expiry | keep case open; require manual evidence |
| Refund destination/evidence | affects return-of-value control | source and model reviewed before implementation | simulate reservation only; no transaction semantics claim |
| Handling-time assumptions | drive queue result | sensitivity across 0.5×/1×/2× | make no superiority recommendation |
| Reviewer access | affects usability claim | up to three willing reviewers using same task | labeled self-review; no usability improvement claim |

Decision log entries must record date, owner, evidence, choice, alternatives, and changed artifacts. External messages, applications, accounts, payments, and deployment require separate explicit authorization.
